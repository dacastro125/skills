## Área 1. Visibilidad del estado, ubicación y feedback inmediato (19 puntos)

|---|---|---|---|
| **1.1** | **Does every display begin with a title or header that describes screen contents?**<br>_¿Cada pantalla comienza con un título o encabezado que describe su contenido?_ | Cada vista/ruta/pantalla define `<title>`, `<h1>` o cabecera (`AppBar`/header) visible que describe exactamente el propósito actual. | Fragmento embebido sin vista completa (`No aplica`) |

| **1.4** | **Do menu instructions, prompts, and error messages appear in the same place(s) on each menu?**<br>_¿Las instrucciones de menú, avisos y mensajes de error aparecen en los mismos lugares en cada menú?_ | Slots consistentes en layout compartido (misma zona superior/inferior/inline para avisos globales, instrucciones de formulario y errores de validación entre vistas). | Componente aislado de una sola vista sin navegación entre menús (`No aplica`) |
| **1.5** | **In multipage data entry screens, is each page labeled to show its relation to others?**<br>_En pantallas multipágina de ingreso de datos, ¿cada página está etiquetada mostrando su relación con las demás?_ | Formularios o wizards multipaso muestran indicador explícito de relación entre pantallas (p. ej. `Paso 2 de 4`, `Stepper`, barra de progreso o título secuencial). | Aplicación de una sola vista o sin flujos multipágina (`No aplica`) |
| **1.29** | **If users must navigate between multiple screens, does the system use context labels, menu maps, and place markers as navigational aids?**<br>_Si el usuario debe navegar entre varias pantallas, ¿usa etiquetas de contexto, mapas de menú y marcadores de ubicación?_ | Navegación entre múltiples vistas incluye breadcrumbs, pestaña activa marcada, índice lateral o marcador de ubicación persistente. | Vista única sin jerarquía ni múltiples pantallas (`No aplica`) |
| **1.7** | **If pop-up windows are used to display error messages, do they allow the user to see the field in error?**<br>_Si se usan ventanas emergentes para mostrar errores, ¿permiten ver el campo que tiene el error?_ | Toasts, popovers o modales de error no cubren ni bloquean el `<input>` con fallo (preferir error inline junto al campo o modal con detalle y foco al volver). | No usa popups/toasts para mostrar errores ni tiene formularios (`No aplica`; si usa `z-index` dinámico no observable estáticamente, `No verificable estáticamente`) |
| **1.8** | **Is there some form of system feedback for every operator action?**<br>_¿Existe alguna forma de retroalimentación del sistema para cada acción del usuario/operador?_ | Todo clic, envío, guardado, borrado o llamada asíncrona produce feedback visible inmediato (`disabled`/spinner/toast/`aria-live`/cambio de estado). | Documento puramente estático de solo lectura sin acciones interactivas (`No aplica`) |
| **1.9** | **After the user completes an action (or group of actions), does the feedback indicate that the next group of actions can be started?**<br>_Tras completar una acción (o grupo de acciones), ¿la retroalimentación indica que puede iniciarse el siguiente grupo?_ | Al finalizar una operación o paso (envío, carga, guardado), la UI limpia spinners, habilita el siguiente control e informa de forma inequívoca que se puede continuar. | Sin acciones secuenciales ni procesos con inicio/fin (`No aplica`) |
| **1.10** | **Is there visual feedback in menus or dialog boxes about which choices are selectable?**<br>_¿Hay retroalimentación visual en menús o diálogos sobre qué opciones se pueden seleccionar?_ | Elementos interactivos en menús o diálogos usan semántica nativa (`<button>`, `<a>`, `<option>`) o roles + estilos claros que distinguen ítems elegibles de texto pasivo o `:disabled`. | Sin menús ni cuadros de diálogo (`No aplica`) |
| **1.11** | **Is there visual feedback in menus or dialog boxes about which choice the cursor is on now?**<br>_¿Hay retroalimentación visual en menús o diálogos sobre qué opción tiene el cursor actualmente?_ | Estados `:hover` y `:focus-visible` definidos y perceptibles (contraste suficiente, no `outline: none` sin reemplazo) sobre opciones de menú y diálogos. | Sin menús ni controles seleccionables (`No aplica`) |
| **1.12** | **If multiple options can be selected in a menu or dialog box, is there visual feedback about which options are already selected?**<br>_Si pueden seleccionarse múltiples opciones en un menú o diálogo, ¿hay retroalimentación visual de cuáles ya están elegidas?_ | En multiselección (checkboxes, chips, tablas), todos los elementos elegidos muestran marca persistente (`checked`, `aria-checked`, chip/contador) más allá del hover. | No hay selección múltiple (`No aplica`) |
| **1.13** | **Is there visual feedback when objects are selected or moved?**<br>_¿Existe retroalimentación visual cuando se seleccionan o mueven objetos?_ | Al seleccionar o arrastrar elementos (cards, filas, drag-and-drop), cambia cursor/elevación/borde/zona de destino (`aria-grabbed`/placeholder visual). | Sin selección de objetos ni interacción de arrastre (`No aplica`) |
| **1.16** | **If there are observable delays (greater than fifteen seconds) in the system's response time, is the user kept informed of the system's progress?**<br>_Si hay demoras observables (mayores a 15 segundos) en el tiempo de respuesta, ¿se mantiene informado al usuario del progreso?_ | Operaciones asíncronas, subidas o procesos lentos muestran barra/progreso determinado o indeterminado, mensaje de estado y opción de cancelar cuando aplique. | Operaciones 100% síncronas e instantáneas locales sin red ni procesos largos (`No aplica`) |
| **1.25** | **Is the menu-naming terminology consistent with the user's task domain?**<br>_¿La terminología de los nombres de menú es coherente con el dominio de tareas del usuario?_ | Rótulos de navegación y menús usan términos del dominio del usuario final (p. ej. «Mis citas», «Facturas») y no nombres técnicos de tablas o rutas internas. | Sin menús ni navegación (`No aplica`; si requiere conocer jerga de nicho no explicada en README, `No verificable estáticamente`) |
| **1.26** | **Does the system provide visibility: that is, by looking, can the user tell the state of the system and the alternatives for action?**<br>_¿El sistema ofrece visibilidad, es decir, con solo mirar el usuario sabe el estado del sistema y las alternativas de acción?_ | De un vistazo la interfaz expone el estado actual (conectado, borrador, filtro activo, total) y los CTA disponibles sin ocultar acciones clave bajo gestos secretos. | Fragmento decorativo sin estado ni acciones (`No aplica`) |

## Área 2. Lenguaje humano, mundo real y mapeo natural (23 puntos)

| ID | Criterio original de Pierotti (EN / ES) | Qué inspeccionar en Diseño UI y Código moderno | Cuándo marcar `No aplica` / `No verificable estáticamente` |
|---|---|---|---|
| **2.1** | **Are icons concrete and familiar?**<br>_¿Los iconos son concretos y familiares?_ | Iconos representan objetos o acciones reconocibles (lupa=buscar, papelera=eliminar, lápiz=editar) evitando metáforas crípticas o inventadas sin texto. | Interfaz sin iconos (`No aplica`) |
| **2.5** | **If shape is used as a visual cue, does it match cultural conventions?**<br>_Si se usa la forma como señal visual, ¿coincide con convenciones culturales?_ | Formas visuales siguen convenciones (círculo=radio único, cuadrado con check=múltiple, triángulo=advertencia, X=cerrar). | Sin formas codificadas como señal visual (`No aplica`) |
| **2.6** | **Do the selected colors correspond to common expectations about color codes?**<br>_¿Los colores elegidos corresponden a expectativas comunes sobre códigos de color?_ | Colores semánticos respetan expectativas (rojo=error/peligro, ámbar=advertencia, verde=éxito/confirmado, azul=informativo) sin invertir significados. | UI estrictamente monocromática sin colores de estado (`No aplica`) |
| **2.2** | **Are menu choices ordered in the most logical way, given the user, the item names, and the task variables?**<br>_¿Las opciones de menú están ordenadas de la forma más lógica según el usuario, los nombres y las variables de la tarea?_ | Opciones de menú siguen un criterio lógico para la tarea (frecuencia de uso, jerarquía, flujo de trabajo o alfabético cuando no hay orden natural). | Menú con menos de 2 opciones o inexistente (`No aplica`) |
| **2.3** | **If there is a natural sequence to menu choices, has it been used?**<br>_Si existe una secuencia natural para las opciones del menú, ¿se ha utilizado?_ | Secuencias con orden natural del mundo real (Días L–D, Meses, Pasos cronológicos, Dirección País→Ciudad) respetan ese orden sin desordenar ni alfabetizar a la fuerza. | Opciones sin secuencia natural inherente (`No aplica`) |
| **2.4** | **Do related and interdependent fields appear on the same screen?**<br>_¿Los campos relacionados e interdependientes aparecen en la misma pantalla?_ | Campos interdependientes (fecha inicio/fin, país/código postal, contraseña/confirmación, precio/moneda) conviven en la misma vista o sección. | Formulario de campo único o sin campos dependientes (`No aplica`) |
| **2.7** | **When prompts imply a necessary action, are the words in the message consistent with that action?**<br>_Cuando los avisos implican una acción necesaria, ¿las palabras del mensaje son coherentes con esa acción?_ | El texto de botones y avisos coincide exactamente con la acción ejecutada (si pregunta «¿Descartar cambios?», botones «Descartar» / «Seguir editando» en vez de «Sí/No»). | Sin diálogos o avisos que impliquen acción (`No aplica`) |
| **2.8** | **Do keystroke references in prompts match actual key names?**<br>_¿Las referencias a teclas en los mensajes coinciden con los nombres reales de las teclas?_ | Si se muestran atajos en UI/tooltips, los nombres coinciden con la plataforma real (`Ctrl`/`Cmd`, `Esc`, `Enter`, `Tab`) sin referencias falsas o desactualizadas. | La interfaz no menciona teclas o atajos en su copy (`No aplica`) |
| **2.9** | **On data entry screens, are tasks described in terminology familiar to users?**<br>_En pantallas de ingreso de datos, ¿las tareas se describen con terminología familiar para los usuarios?_ | Instrucciones y descripciones de formularios emplean vocabulario del usuario, evitando términos de base de datos, API o implementación. | Sin pantallas o secciones de ingreso de datos (`No aplica`) |
| **2.10** | **Are field-level prompts provided for data entry screens?**<br>_¿Se proporcionan indicaciones/ayudas a nivel de campo en las pantallas de ingreso de datos?_ | Campos con restricciones, formatos esperados o impacto no obvio cuentan con helper text visible (`aria-describedby`) o ejemplo claro junto al input. | Sin formularios ni campos de entrada (`No aplica`) |
| **2.11** | **For question and answer interfaces, are questions stated in clear, simple language?**<br>_En interfaces de pregunta y respuesta, ¿las preguntas están redactadas en lenguaje claro y sencillo?_ | Encuestas, asistentes y flujos tipo pregunta-respuesta formulan preguntas directas, concretas y en lenguaje llano sin doble negación ni tecnicismos. | Sin interfaz de preguntas y respuestas ni wizard conversacional (`No aplica`) |
| **2.12** | **Do menu choices fit logically into categories that have readily understood meanings?**<br>_¿Las opciones de menú encajan lógicamente en categorías con significados fáciles de comprender?_ | Categorías de navegación y menús agrupan ítems afines bajo etiquetas comprensibles (sin cajones de sastre ambiguos como «Varios» u «Otros» injustificados). | Sin menús categorizados (`No aplica`) |
| **2.13** | **Are menu titles parallel grammatically?**<br>_¿Los títulos de menú mantienen paralelismo gramatical?_ | Títulos de secciones/menús hermanos mantienen paralelismo gramatical (todos sustantivos o todos verbos en infinitivo, sin mezclar formas inconsistentes). | Un único menú/sección o sin títulos de menú (`No aplica`) |
| **2.14** | **Does the command language employ user jargon and avoid computer jargon?**<br>_¿El lenguaje de comandos usa la jerga del usuario y evita la jerga informática?_ | Acciones y controles evitan jerga informática (no usar «Persistir entidad», «Payload», «Null», «Flush cache» en apps para público general). | Herramienta puramente técnica para desarrolladores donde el término es dominio exacto (`No aplica`) |
| **2.15** | **Are command names specific rather than general?**<br>_¿Los nombres de comandos son específicos en lugar de genéricos?_ | Botones y CTAs llevan verbos específicos al objeto («Guardar borrador», «Eliminar cuenta», «Enviar pedido») evitando botones vagos («Aceptar», «OK», «Procesar»). | Sin botones o comandos de acción (`No aplica`) |
| **2.17** | **Are input data codes meaningful?**<br>_¿Los códigos de datos de entrada tienen significado claro?_ | Códigos o identificadores visibles al usuario muestran etiquetas legibles o códigos con sentido (nunca UUIDs crudos, IDs numéricos huérfanos ni claves opacas). | No presenta códigos de entrada/selección (`No aplica`) |
| **2.18** | **Have uncommon letter sequences been avoided whenever possible?**<br>_¿Se han evitado secuencias de letras poco comunes siempre que ha sido posible?_ | Etiquetas, atajos o códigos introducidos manualmente evitan abreviaturas raras o siglas inventadas difíciles de memorizar (`CFG_USR_M1`). | Sin códigos ni abreviaturas de entrada mostradas al usuario (`No aplica`) |
| **2.19** | **Does the system automatically enter leading or trailing spaces to align decimal points?**<br>_¿El sistema alinea automáticamente los puntos decimales añadiendo espacios iniciales o finales?_ | Valores decimales en tablas o resúmenes numéricos usan `font-variant-numeric: tabular-nums` / alineación decimal derecha en CSS/componentes. | No muestra tablas ni listas de cifras decimales (`No aplica`) |
| **2.20** | **Does the system automatically enter a dollar sign and decimal for monetary entries?**<br>_¿El sistema introduce automáticamente el signo monetario y decimales en entradas de dinero?_ | Campos o vistas monetarias muestran símbolo/código de moneda explícito (`$`, `€`, `COP`) y formato decimal adecuado (`Intl.NumberFormat` / máscara no bloqueante). | La app no maneja ni muestra importes monetarios (`No aplica`) |
| **2.21** | **Does the system automatically enter commas in numeric values greater than 9999?**<br>_¿El sistema añade automáticamente separadores de miles en valores numéricos mayores a 9999?_ | Números de cinco o más cifras (>9999) se formatean con separadores de miles legibles (`Intl.NumberFormat`), sin comprometer la edición en inputs numéricos. | No muestra ni captura cifras >= 10000 (`No aplica`) |
| **2.22** | **Do GUI menus offer activation: that is, make obvious how to say "now do it"?**<br>_¿Los menús gráficos dejan claro cómo activar o ejecutar la acción («hacerlo ahora»)?_ | En formularios, modales y menús de decisión el botón de activación/ejecución principal (`type="submit"` / CTA primario) es visualmente inequívoco. | Sin vistas o diálogos con ejecución de acción (`No aplica`) |
| **2.23** | **Has the system been designed so that keys with similar names do not perform opposite (and potentially dangerous) actions?**<br>_¿Se ha diseñado de modo que teclas con nombres similares no ejecuten acciones opuestas y potencialmente peligrosas?_ | No se asignan combinaciones o botones casi idénticos a acciones opuestas o destructivas (p. ej. `Guardar` junto a `Reiniciar todo` con igual apariencia o atajos contiguos). | Sin atajos configurados ni pares de acciones opuestas de riesgo (`No aplica`) |
| **2.24** | **Are function keys labeled clearly and distinctively, even if this means breaking consistency rules?**<br>_¿Las teclas de función están etiquetadas de forma clara y distintiva, incluso si ello implica romper reglas de consistencia?_ | Controles/teclas con efectos críticos o de alcance especial están rotulados de forma inequívoca e inconfundible aunque rompan simetría visual estándar (ej. botón rojo «Eliminar definitivamente»). | Sin acciones críticas o destructivas en la interfaz (`No aplica`) |

## Área 3. Control del usuario, reversibilidad y navegación sin trampas (16 puntos)

| ID | Criterio original de Pierotti (EN / ES) | Qué inspeccionar en Diseño UI y Código moderno | Cuándo marcar `No aplica` / `No verificable estáticamente` |
|---|---|---|---|
| **3.4** | **When a user's task is complete, does the system wait for a signal from the user before processing?**<br>_Cuando el usuario completa una tarea, ¿espera el sistema una señal explícita antes de procesar?_ | La app no envía ni aplica cambios irreversibles automáticamente sin acción explícita del usuario (salvo guardado automático explícito y reversible de borrador). | Vista pasiva sin tareas de envío ni procesamiento mutante (`No aplica`) |
| **3.6** | **Are users prompted to confirm commands that have drastic, destructive consequences?**<br>_¿Se solicita confirmación al usuario ante comandos con consecuencias drásticas o destructivas?_ | Acciones destructivas (eliminar registro, cerrar cuenta, sobrescribir, cancelar compra) muestran confirmación clara indicando exactamente qué se perderá. | Sin acciones destructivas o irreversibles (`No aplica`) |
| **3.20** | **Do function keys that can cause serious consequences have an undo feature?**<br>_¿Las teclas de función que causan consecuencias graves cuentan con función de deshacer?_ | Atajos rápidos o botones con impacto serio (borrar, archivar masivo) ofrecen confirmación previa o `Deshacer` inmediato (toast con botón `Undo`). | Sin atajos ni botones rápidos de alto impacto (`No aplica`) |
| **3.7** | **Is there an "undo" function at the level of a single action, a data entry, and a complete group of actions?**<br>_¿Existe función «Deshacer» a nivel de una acción individual, una entrada de datos y un grupo completo de acciones?_ | Acciones editables o destructivas reversibles soportan «Deshacer» (a nivel de campo/Ctrl+Z, registro individual o acción en lote). | Interfaz sin edición, creación ni eliminación de estado (`No aplica`) |
| **3.8** | **Can users cancel out of operations in progress?**<br>_¿Pueden los usuarios cancelar operaciones en curso?_ | Operaciones en curso (peticiones `fetch`/`axios` mediante `AbortController`, subidas, exportaciones o wizards) tienen botón `Cancelar` que aborta y limpia estado. | Solo acciones instantáneas y atómicas locales sin procesos en curso (`No aplica`) |
| **3.21** | **Can users easily reverse their actions?**<br>_¿Pueden los usuarios revertir sus acciones con facilidad?_ | El usuario puede revertir con un clic selecciones, filtros, toggles o ediciones recientes sin tener que recargar la página ni reiniciar el flujo. | Vista de solo lectura sin estado mutable (`No aplica`) |
| **3.22** | **If the system allows users to reverse their actions, is there a retracing mechanism to allow for multiple undos?**<br>_Si permite revertir acciones, ¿existe un mecanismo para múltiples deshacer consecutivos?_ | Editores, tableros o flujos con historial de edición mantienen pila de historial (*undo stack*) para deshacer múltiples cambios consecutivos. | Sin flujo de edición multi-acción ni editor de contenido (`No aplica`) |
| **3.10** | **Can users reduce data entry time by copying and modifying existing data?**<br>_¿Pueden reducir el tiempo de captura copiando y modificando datos existentes?_ | Flujos repetitivos permiten duplicar, copiar registros previos o reutilizar datos guardados (ej. «Usar misma dirección de facturación»). | Sin captura repetitiva ni registros reutilizables (`No aplica`) |
| **3.12** | **If menu lists are long (more than seven items), can users select an item either by moving the cursor or by typing a mnemonic code?**<br>_Si las listas de menú son largas (más de 7 ítems), ¿pueden seleccionar moviendo el cursor o escribiendo un código mnemotécnico?_ | Listas/selectores con más de 7 opciones ofrecen búsqueda/filtrado interactivo (`filter`/combobox) o navegación ágil por teclado. | Todas las listas o menús tienen <= 7 opciones (`No aplica`) |
| **3.13** | **If the system uses a pointing device, do users have the option of either clicking on menu items or using a keyboard shortcut?**<br>_Si usa ratón/puntero, ¿pueden elegir entre hacer clic en ítems del menú o usar un atajo de teclado?_ | Toda opción de menú accionable con puntero es activable igualmente desde teclado (`Enter`/`Space`/atajos accesibles) sin depender solo de `onMouseOver` o `onClick` en `<div>`. | Sin menús interactivos (`No aplica`) |
| **3.14** | **Are menus broad (many items on a menu) rather than deep (many menu levels)?**<br>_¿Los menús son amplios (más ítems por nivel) en lugar de profundos (muchos niveles anidados)?_ | Arquitectura de navegación prioriza menús claros y amplios sobre submenús profundamente anidados (>2–3 niveles de hover frágiles). | Menú de un solo nivel sin anidamiento (`No aplica`) |
| **3.15** | **If the system has multiple menu levels, is there a mechanism that allows users to go back to previous menus?**<br>_Si hay varios niveles de menú, ¿existe un mecanismo para regresar a los menús anteriores?_ | En menús multinivel, subpaneles o drawers anidados existe siempre un control visible para regresar al nivel anterior (`Atrás`, breadcrumb, botón volver). | Navegación plana de un solo nivel (`No aplica`) |
| **3.16** | **If users can go back to a previous menu, can they change their earlier menu choice?**<br>_Si pueden volver a un menú anterior, ¿pueden cambiar su elección previa?_ | Al volver atrás desde un submenú, modal o paso previo, el usuario puede cambiar su elección anterior sin quedarse bloqueado ni obligado a empezar de cero. | Sin menús/pasos secuenciales multinivel (`No aplica`) |
